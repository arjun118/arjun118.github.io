```go
func normalize(s string) string {
	runes := []rune(strings.TrimSpace(s))
	i := 0
	for i < len(runes) {
		r := runes[i]

		if unicode.IsLetter(r) || unicode.IsDigit(r) {
			break
		}

		i++
	}
	return strings.ToLower(string(runes[i:]))
}
```

# Architecture

I have iteratively implemented the architecture. i will split into phases

## Phase 1: [BASIC TRIE - V1 Dataset]

In this phase ,we will take the V1 Dataset

```bash
❯ wc -l aol_queries.txt
# 433614 aol_queries.txt
```

and build a trie. before going into any implementation details ,lets look at how our trie is implemented in go

```go

type Reco struct {
	Word string
	Freq int64
}


type Node struct {
	Val      rune
	Children map[rune]*Node
	IsWord   bool
	Freq     int64
	Top      []Reco
}
type Trie struct {
	Root       *Node
	K          int
	CacheDepth int
}
```

this is just like basic tree but a node can have many children. field specifics - what we store is below

### Node

1. a node in our trie
2. `Val`: the character this node holds (redundant ,no need to store, i just kept this because it gave me clarity while debugging)
3. `Children`: the children of this node
4. `IsWord`: will be true if a word is formed until the node
5. `Freq`: the frequency of this word/phrase from our datset
6. `Top`: we cache the top-K most occuring words(using `Reco` type - which has the word (phrase) and its freq) at this node, (optimization)

### Trie

1. `Root`: also a Node with `Val=""`
2. `K`: for this phase 1 implementation, we initalize this trie with a number K, the number of suggestions/auto-completes to be returned per query
3. `CacheDepth`: see point 6 from `Node`, we limit the depth post which no `Top` is populated at the node in the trie. we will cache the shallow nodes. this can be set to the number x where `x=the average number of characters a user types before selecting a suggestion'`. this helps us save memory when all the queries are answered from an in-memory trie (or prefix-index hash map)

### Building the Trie

```go
func BuildTrie(ipfile string) *Trie {
	trie := NewTrie()
	file, err := os.Open(ipfile)
	if err != nil {
		panic("error opening file,cannot build trie")
	}
	defer file.Close()
	scanner := bufio.NewScanner(file)
	for scanner.Scan() {

		line := strings.TrimSpace(scanner.Text())
		phrase, freq, ok := ParseLine(line)
		if ok {
			trie.Insert(phrase, freq)
		}

	}
	if err := scanner.Err(); err != nil {
		panic(fmt.Sprintf("failed build trie..%s", err.Error()))
	}
	return trie
}
```

1. we traverse our dataset line by line, parsing each line to give us a phrase and a frequency
   our insert is also simple

```go
func (t *Trie) Insert(s string, freq int64) {
	// insert and return the freq of the word
	node := t.Root
	for _, x := range s {
		if node.Children == nil {
			// if the node doesnot have children -lets initialize here
			node.Children = make(map[rune]*Node)
		}
		nextnode, ok := node.Children[x]
		if !ok {
			// add new
			nextnode = NewNode()
			nextnode.Val = x
			node.Children[x] = nextnode
		}
		node = nextnode
	}
	node.IsWord = true
	node.Freq = freq
}
```

with this we can easily search our trie using

```go
func (t *Trie) Search(s string) (bool, bool, int64, *Node) {
	// search for a string in the trie
	// first bool -> if the string exists
	// second bool -> if the string is a word or not
	node := t.Root
	for _, x := range s {
		nextnode, ok := node.Children[x]
		if !ok {
			return false, false, 0, nil
		}
		node = nextnode
	}
	return true, node.IsWord, node.Freq, node
}
```

## Phase 2: [PREFIX INDEX HASH MAP - V1 Dataset]

1. what will include here is a simple hashmap. every prefix that can be formed while traversing the trie will be a `key` for the hashmap. the value will be what want to return if that prefix is typed (the search query) i.e a list of top-K words.

```go
type PrefixIndex map[string][]Reco

func NewPrefixIndex() PrefixIndex {
	return PrefixIndex{}
}
```

that's it, our prefix index is that simple.we can easily build the prefix index from our trie using

```go
func (t *Trie) walkForIndex(node *Node, prefix string, pi PrefixIndex) []Reco {
	cands := make([][]Reco, 0, len(node.Children)+1)
	if node.IsWord {
		cands = append(cands, []Reco{{Word: prefix, Freq: node.Freq}})
	}
	for key, child := range node.Children {
		cands = append(cands, t.walkForIndex(child, prefix+string(key), pi))
	}
	var top []Reco
	if len(cands) == 1 {
		top = cands[0] // already ≤ k meaning sorted
	} else if len(cands) > 1 {
		top = mergeTopK(cands, t.K)
	}
	pi[prefix] = top
	return top
}
```

notice the `mergeTopk`, we wont re-calcualte the top-K words for every node, we will perform a mergesort on all the children top-k words

```go
func mergeTopK(lists [][]Reco, k int) []Reco {
	h := &headHeap{}
	heap.Init(h)
	for _, l := range lists {
		if len(l) > 0 {
			heap.Push(h, head{l, 0})
		}
	}
	out := make([]Reco, 0, k)
	for h.Len() > 0 && len(out) < k {
		t := heap.Pop(h).(head) // take the largest current head
		out = append(out, t.list[t.idx])
		if t.idx+1 < len(t.list) { // that list still has elements?
			heap.Push(h, head{t.list, t.idx + 1}) // put the next one in the race
		}
	}
	return out
}
```

please find the heap definitons here: [heap](https://github.com/arjun118/system_design_implementations/blob/main/search_autocomplete/internal/trie/heap.go)

search and suggesting from our prefix index becomes extremely simple now.we dont need to traverse anything to get the words to suggest, we just need to ask

```go

func (pi PrefixIndex) Suggest(prefix string) []string {
	recos, ok := pi[prefix]
	if !ok {
		return nil
	}
	result := make([]string, 0, len(recos))
	for _, r := range recos {
		result = append(result, r.Word)
	}
	return result
}
```

so instead of working on that architecture, i have moved to a 3 tier serving arch, explained below

## Phase 4: [3-TIER SERVING]

### The three tiers

1. in-memory: prefix-index hash map of n most frequently occuring prefixes (this should ideally be n most searched queries (by the user if implementing at a user level))
2. redis: lfu (least frequently used cache) of m most frequently occuring prefixes - this should be most searched in realword case
3. db: mongodb collection containing all the requried data of our 9.6 mil queries (we will have a robust seeder to seed the db)

obviously , m>>n. we keep a very small subset of queries in in-memory state and considerable number of prefix in redis.

### Concurrency

we will use go-routines to build our prefix-indexes for different prefixes. but spinning a new go-routine for every child of a prefix defeats the purpose and we cannot continue with our seeder on local. we will have bounded concurrency here

#### channels

two buffered channels, 1 for processBucket to enqueue build jobs and 1 for index building workers to enqueue results

```go
var (
	indexBuildJobs = make(chan BucketMetrics, 5)
	indexResults   = make(chan PI, 5)
)
```

#### workers

1. `IndexBuildingWorkers`

- consumes from `indexBuildJobs` and sends onto `indexResults`
- 6 workers at anytime
- i used `const memoryBudget = 500 * MB` , a memory budget of 500mb in our seeder, and 6 index building worker running at any time ensures that the seeder comfortably executes, leaving the head room for mongo process and other processes (i will detail these in a future blog)
- with this config, my system memory usage never exceeds `10GB` (needs better explaninability as to why it is 10gb, i will write that in a future blog as learnings, sorry :) )

```go
func IndexBuildingWorkers(path string, wg *sync.WaitGroup) {
	for range 6 {
		// there are 6 workers at any time - working on building prefix indexes
		// each's memory limit is capped to 500mb (done via estimated memory from the processBucket)
		wg.Go(func() {
			f, err := os.Open(path) // one handle per worker
			if err != nil {
				panic(err)
			}
			defer f.Close()
			for child := range indexBuildJobs {
				estimated := float64(child.DistinctPrefixes) * bytesPerPrefix
				fmt.Printf(
					"BUILD  %-10s prefixes=%d estimated=%.2f MB\n",
					child.Prefix,
					child.DistinctPrefixes,
					estimated/(1024*1024),
				)
				pi := buildPrefixIndex(f, child)
				fmt.Printf("QUEUEING - MERGE  %-10s prefixes=%d\n",
					child.Prefix,
					len(pi),
				)
				indexResults <- pi
			}

		})
	}
}
```

1. the `buildPrefixIndex` is simialr to how we built our prefix-index in phase -2 but this will be done without a trie-intermediate

```go
func buildPrefixIndex(f *os.File, child BucketMetrics) PI {
	_, err := f.Seek(child.Start, io.SeekStart)
	if err != nil {
		panic(err)
	}
	limited := io.LimitReader(f, child.End-child.Start)
	scanner := bufio.NewScanner(limited)
	pi := make(PI)
	for scanner.Scan() {
		phrase, freq, ok := trie.ParseLine(scanner.Text())
		if !ok {
			continue
		}
		runeList := []rune(phrase)
		for i := 1; i <= len(runeList); i++ {
			pref := string(runeList[:i])
			if pi[pref] == nil {
				hp := &trie.RecHeap{}
				heap.Init(hp)
				pi[pref] = hp
			}
			if pi[pref].Len() < k {
				heap.Push(pi[pref], trie.Reco{Word: phrase, Freq: freq})
			} else {
				if pi[pref].Top().Freq < freq {
					heap.Pop(pi[pref])
					heap.Push(pi[pref], trie.Reco{Word: phrase, Freq: freq})
				}
			}
		}
	}
	if scanner.Err() != nil {
		panic(scanner.Err())
	}
	return pi

}
```

1. our `mergeIntoMongo` function, will merge the exsiting doc for the prefix (if already present in our mongodb colleciton) with the incoming one ,preserving the top-k words. it does this in batches or `batchSize=1000`. code here: [mergeIntoMongo](https://github.com/arjun118/system_design_implementations/blob/main/search_autocomplete/cmd/seeder/main.go)

### Why only 1 MongoMergeWorker

consider this, you are processing with 2 mongo merge workers, and one of the worker is processing prefix-index for bucket `th` and other is processing prefix-index for bucket `to`.

both will update the document (they will update the top-k words) in mongodb with where `prefix=t`. they will race to update this, without proper locking semantics, there will be lost updates and race conditions. this can be solved by parititioning our mongo instance and having different mongo merge workers udpate different shards. i haven't done that in this arch, will include that in next steps and complete.

### Scan

when given a prefix, to our `Scan` function we will scan the file (our V2 dataset) to find out the children bucket boundaries and returns a `ScanResult` which our processBucket can use

```go
type ScanResult struct {
	Children []BucketMetrics
}
```

```go
func Scan(f *os.File, prefix string, start int64, end int64) ScanResult {
	_, err := f.Seek(start, io.SeekStart)
	if err != nil {
		panic(err)
	}
	limited := io.LimitReader(f, end-start)
	scanner := bufio.NewScanner(limited)
	prefixRunes := []rune(prefix)
	prefixLen := len(prefixRunes)
	var children []BucketMetrics
	var currentChild string
	var childStart int64
	var childDP int64
	childDP = 1
	prevPhrase := ""
	var offset int64
	for scanner.Scan() {
		line := scanner.Text()
		//advance offset
		lineSize := int64(len(line) + 1)
		offset += lineSize
		phrase, _, ok := trie.ParseLine(line)
		if !ok {
			continue
		}
		runes := []rune(phrase)
		// processing children, if have no extra text after the prefix for the current prefix, lets continue
		if len(runes) <= prefixLen {
			continue
		}
		// if the prefix of the current phrase doesnot equal to prefix
		// continue - ideally this should not happend if we have built our canonical sorted dataset correclty - safety check
		if prefixLen > 0 && !strings.HasPrefix(phrase, prefix) {
			panic(fmt.Sprintf(
				"phrase %q outside prefix bucket %q",
				phrase,
				prefix,
			))
		}
		// child= prefix + next rune.
		child := string(runes[:prefixLen+1])
		// new child bucket
		// but here the currentCHild is techncially previousChild isnt it?
		if child != currentChild {
			// complete prev child
			if currentChild != "" {
				children = append(children, BucketMetrics{
					Prefix:           currentChild,
					Start:            childStart,
					End:              start + offset - lineSize,
					DistinctPrefixes: childDP,
				})
			}
			//new child
			currentChild = child
			// since we already increased the offset, we need to substract the lineSize from offset to get the start of the
			// new child
			childStart = start + offset - lineSize
			childDP = 0
			// reset lcp for every child.
			prevPhrase = ""
		}
		// count new distinct prefixes
		childDP += int64(
			len(runes) - max(prefixLen+1, lcp(phrase, prevPhrase)),
		)
		prevPhrase = phrase
	}
	if err := scanner.Err(); err != nil {
		panic(err)
	}
	//close final child
	if currentChild != "" {
		children = append(children, BucketMetrics{
			Prefix:           currentChild,
			Start:            childStart,
			End:              start + offset,
			DistinctPrefixes: childDP,
		})
	}

	return ScanResult{
		Children: children,
	}
}
```
